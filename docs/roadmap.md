# Roadmap

See `docs/roadmap-v2.md` for the user-defined "North Star" vision (15
goals, v1-v5 milestones), a gap analysis against the current codebase,
and the staged Tier 1/2/3 feature plan currently being worked
sequentially (tasks #56-#61 onward). This file remains the record of
what's shipped vs. explicitly deferred at the subsystem level.

## Shipped in v0.1 (this repository)

- Kernel: event bus, structured logger, permission manager, plugin loader, agent router, context manager, generic DAG executor, config.
- Providers: `AIProvider` interface + Anthropic, OpenAI, Ollama, LM Studio (local, OpenAI-compatible), Mock, with a registry that resolves the active one from config/env.
- Tools: shell, git, filesystem, each with capabilities/requirements/permissions/health-check.
- Memory: short-term, session, project, global scopes + brute-force vector search for semantic recall.
- Agents: Generic, Code, Research, Git, Testing, GitHub Trending, routed by capability. See below for the five later-added named specialists (Reviewer, Security Auditor, DevOps, UI Designer, Architect).
- Planner: goal → task graph via the active provider, with dependency-aware parallel execution, retries, and rollback hooks.
- Workflow engine: JSON-defined step graphs (`agent:<capability>` / `tool:<name>`) on the same DAG executor.
- Scheduler: cron-based recurring jobs.
- CLI (`ash init/doctor/status/provider/plugin/plan/run/chat/memory/logs`).
- REST API (`/chat /plan /execute /workflow /agents /providers /tools /tasks /memory /logs /health`).
- SDK facade (`AshOS` class) for embedding in other Node apps.
- Plugin system (manifest + `PluginHost` contract) with git/shell reference plugins.
- Dashboard (Vite + React + Tailwind v4 + shadcn/ui-style components) with status, inbox, plan, workflow, memory, logs, chat, Innovation, and Trending tabs, a responsive sidebar nav (drawer on mobile), and light/dark theming. Providers/Agents/Tools don't have their own tabs (dropped as unused UI surface) — all three are still fully reachable via `ash provider`/`ash status` and `GET /providers`/`/agents`/`/tools`.
- Unit + integration tests (vitest) across kernel/providers/tools/memory/agents/planner/workflow/scheduler/sdk/api/cli/innovation.
- CI (GitHub Actions: typecheck + test), Docker + docker-compose (with an Ollama sidecar).
- **Innovation Intelligence**: continuous opportunity discovery — one `IntelligenceAgent` per domain (market, GitHub, community, research, workflow, competitor), each backed by a deterministic offline mock `Collector` by default (pluggable for a real network-backed one, same extension path as tools/providers); signals feed a JSON-backed `KnowledgeGraph`; an `OpportunityEngine` merges related signals (tag-overlap similarity) into ranked `Opportunity` records scored across all 15 dimensions from the design spec via a pure, dependency-free `ScoringEngine`; a `BuilderProfileStore` learns which categories the user favors (with a `reinforce()` hook for the Learning Loop); an idea lifecycle state machine (`captured -> ... -> released`, with archive/revive); a `DailyBriefGenerator` ranks opportunities and asks the configured research provider for a narrative, falling back gracefully offline. CLI (`ash innovation discover/list/show/brief/profile/collectors`) and REST API (`/innovation/*`). See `docs/innovation.md`.
- **AshOS Intelligence — first real slice**: event normalization/dedup (`innovation/events/`) between raw signals and opportunities, with confidence combination across corroborating sources; five real, opt-in collectors (GitHub, Hacker News, Reddit, arXiv, Hugging Face — `ash innovation discover --live`) that never run by default and are isolated per-source so one failing/blocked collector never stops the others; a deterministic Markdown "today's AI news" digest (`ash innovation digest`, `POST /innovation/digest`) built straight from those collectors and saved to `.ashos/innovation/digests/<date>.md`; `RepositoryAnalystAgent` producing cached, structured Repository Intelligence (languages, contributors, dependencies, maintenance/innovation/production-readiness/adoption scores, AshOS-compatibility notes) with pushed-at-based caching so expensive analysis is never repeated needlessly; `TechnologyRadarAgent` classifying every knowledge-graph technology node into emerging/growing/stable/declining/obsolete via a deterministic, evidence-based heuristic. CLI (`ash innovation events/repo/radar/digest`) and REST API (`/innovation/events`, `/innovation/repositories`, `/innovation/radar`, `/innovation/digest`, `/innovation/live-collectors`) and a dashboard Technology Radar + Repository Intelligence + Recent events UI. Full 20-part target architecture and roadmap in `docs/ashos-intelligence.md`.
- **Local Codebase Intelligence** (`codebase/`, North Star roadmap Stage 1 — see `docs/roadmap-v2.md`): indexes the actual local working repository (file tree, per-file language, lightweight regex-based symbol extraction across TypeScript/JavaScript/Python/Go), cached and invalidated by git commit hash so a full re-scan only happens when the repository actually changed. `CodebaseAnalystAgent` (capability `codebase-analyst`) answers "where does X live" via deterministic substring search over the cached index, ranking symbol-name matches ahead of path-only matches. Deliberately distinct from `innovation/repository/`'s external-GitHub-API analysis. CLI (`ash codebase index/find/list`) and REST API (`/codebase/*`). See `docs/codebase-intelligence.md`.
- **Model Router** (`providers/router.ts`, North Star roadmap Stage 2): task-aware provider selection — three tiers (`simple`/`standard`/`complex`), each mapped to a configured provider, with agent capabilities defaulting to a sensible tier so no call site needs to change to benefit. Off by default (`config.router.enabled`); wired into `BaseAgent.execute()` as the single integration point, so every existing agent is routing-aware for free without any agent's own code changing. CLI (`ash provider router status/enable/disable/set`) and REST API (`/providers/router`). See `docs/model-router.md`.
- **Outcome Memory** (`agents/outcome.ts`, North Star roadmap Stage 3): every agent task attempt is auto-recorded into project memory as a `TaskOutcome` (agent, capability, description, success/failure, error, duration) — no opt-in needed, since writing a record has no behavioral effect. Same `BaseAgent.execute()` integration point the router uses. `ash memory list --tag outcome|failure|<agent-name>` surfaces the history. See `docs/outcome-memory.md`.
- **General Knowledge Graph** (`graph/`, North Star roadmap Stage 4): `KnowledgeGraph` (moved from `innovation/graph/` to a shared top-level package, now namespace-aware) backs a second, project-wide instance (`AshOS.knowledgeGraph`, `.ashos/graph.json`) connecting Projects/Agents/Tasks — every agent execution records `task --produced-by--> agent` / `task --part-of--> project` for free via `BaseAgent`, and `CodebaseAnalystAgent` additionally enriches the project node with real language/module data. `ash graph stats/nodes/neighbors/edges` and `/graph*` (including `GET /graph/edges`), plus a dashboard **Graph** tab visualizing the whole graph via a small dependency-free force layout (`dashboard/src/graph-layout.ts`) — nodes colored/filterable by kind, click to highlight a node's connections. See `docs/knowledge-graph.md`.
- **Verification Gate** (`planner/executor.ts`, North Star roadmap Stage 5): a `"code"`-capability task that succeeds is not yet reported done — `TaskExecutor` immediately runs the registered `verify`-capability agent (`TestingAgent` by default) inside the same DAG node, before the node can report success, so a verification failure retries and eventually fails the task with an error that distinguishes "the code agent failed" from "the code was produced but failed verification." On by default (`verify: false` to disable); no-ops if no verify-capable agent is registered. `task:verified`/`task:verification-failed` events. See `docs/verification-gate.md`.
- **Universal Inbox** (`inbox/`, Second Brain roadmap Tier 1 — see `docs/second-brain-roadmap.md`): a single capture point for text/URLs, deterministically auto-classified (github-repo/youtube/tweet/pdf/article/text, no network or LLM call) and persisted as tagged `MemoryManager` project-scope records rather than a new datastore, with best-effort enrichment of `AshOS.knowledgeGraph` (`resource` nodes, linked `repository` nodes for GitHub links). `ash inbox add/list/show/archive`, `/inbox*`, and a dashboard Inbox tab (quick capture + status filter + archive). See `docs/inbox.md`.
- **Memory Timeline** (dashboard-only, Second Brain roadmap Tier 1 — see `docs/second-brain-roadmap.md`): a `Timeline` tab merging the event bus (`GET /events`) and Memory (`GET /memory`) into one chronological, keyword-filterable feed of "everything AshOS has done and remembered" — no backend changes, since both already existed.
- **"Today's Focus" dashboard widget** (Second Brain roadmap Tier 1, now fully shipped — see `docs/second-brain-roadmap.md`): a full-width card atop the Dashboard tab composing unread Inbox count, the top-scored Innovation opportunity, and the most recent Outcome Memory failures from three existing read APIs — no backend changes beyond a small `tag` passthrough already supported by `GET /memory`.
- **Idea Agent** (`innovation/agents/idea-agent.ts`, Second Brain roadmap Tier 2 item 4 — see `docs/second-brain-roadmap.md`): promotes a Universal Inbox item (or raw text) into a scored, deduped Innovation `Opportunity` by reusing the exact same `Signal`/`EventStore`/`OpportunityEngine`/`ScoringEngine` pipeline a discovery cycle uses — no second scoring engine, no separate "idea score." `ash innovation idea capture [content] [--inbox <id>] [--tags] [--domain]`, `POST /innovation/ideas`, and a "Promote to Idea" action on each dashboard Inbox item. See `docs/innovation.md`.
- **Reflection Agent** (`agents/reflection-agent.ts`, Second Brain roadmap Tier 2 item 5 — see `docs/second-brain-roadmap.md`): a daily/weekly/monthly review narrative, same shape as `DailyBriefGenerator` — deterministic Outcome Memory/Inbox/Knowledge Graph summarization (`agents/reflection.ts`) plus a best-effort LLM narrative with a graceful offline fallback. `ash reflect [daily|weekly|monthly]`, `GET /reflect?period=`, and an on-demand "Reflection" card on the dashboard.
- **Cross-store hybrid search** (`search/hybrid-search.ts`, Second Brain roadmap Tier 2 item 6, now complete — see `docs/second-brain-roadmap.md`): `HybridSearch` merges and ranks results from `MemoryManager`, the general `KnowledgeGraph`, `InboxManager`, `VaultManager`, and `WorkspaceManager` into one "find everything about X" list — no new persistence, no duplicate search index. `ash search <query> [--limit] [--semantic]`, `GET /search?q=&limit=&semantic=`, and a dashboard Search tab. See `docs/search.md`.
- **Inbox AI summarization + `WebFetchTool`** (`tools/web-fetch-tool.ts`): `InboxManager.capture()` best-effort asks the active provider for a one-sentence `InboxItem.summary`, grounded in a captured URL's actual fetched page text (not just the URL string) via a new, conservatively-scoped `WebFetchTool` (http/https only, private/loopback/link-local addresses blocked after DNS resolution, no redirects, timeout + size caps, non-text content rejected). Registered generally on `ToolRegistry` (`context.tools.get("web-fetch")`), so any agent can use it. See `docs/inbox.md`.
- **Automatic daily reflection delivery**: `config.reflection` (on by default) plus `AshOS.startScheduledJobs()` registers a cron job — only when the API server process actually starts, never from a short CLI call or a test — that generates and saves a daily reflection to `.ashos/reflections/<period>-<date>.json` (`agents/reflection-store.ts`). The dashboard's Reflection card checks for today's saved copy on load and shows it immediately, no click needed. `ash reflect --save/--cached`, `GET /reflect?save=true/?cached=true`.
- **Five named specialist agents** (North Star roadmap goal #5, closing the Multi-Agent Collaboration gap): Reviewer (`review`/`code-review`), Security Auditor (`security-audit`), DevOps (`devops`), UI Designer (`ui-design`), and Architect (`architecture`) — each a role-specific system prompt over the active provider, following the exact `CodeAgent` shape (optional `task.input.file` to read for context or write the produced artifact). Reachable via the Planner (its system prompt now names all five capabilities), a workflow step (`agent:review`, ...), or `AshOS.runAgent()` directly — no dedicated CLI/REST surface, same as Code/Research/Git/Testing.
- **Knowledge Vault** (`vault/`, Second Brain roadmap Tier 3 item 7 — see `docs/second-brain-roadmap.md`): curated, long-form notes with links between them, one step further triaged than a raw Inbox capture. Same no-new-persistence-engine convention as Inbox: `VaultManager` notes are `MemoryManager` project-scope records tagged `vault`, and note-to-note links are `relates-to` edges on the general `KnowledgeGraph` (new `note` node kind) rather than a second graph. A note can be written directly or promoted from an Inbox item (marks the source item reviewed, same "Promote to X" pattern as the Idea Agent). `ash vault add/promote/list/show/archive/link/backlinks`, `/vault*`, a dashboard Vault tab, and a "Promote to Vault" button on each Inbox item. Also wired into `HybridSearch`. See `docs/knowledge-vault.md`.
- **Project Workspaces** (`workspace/`, Second Brain roadmap Tier 3 item 7, closing it out — see `docs/second-brain-roadmap.md`): a real, persisted `Project`/`ProjectTask`/`Milestone` data model, distinct from the label-only `project` Knowledge Graph node `BaseAgent` auto-creates per working directory. Same no-new-persistence-engine convention: `WorkspaceManager` records are `MemoryManager` project-scope records tagged `workspace-project`/`workspace-task`/`workspace-milestone`. Tasks/milestones get new `todo`/`milestone` Knowledge Graph node kinds — deliberately distinct from the ephemeral `task` kind `BaseAgent` uses for agent-run records — linked to their project via `part-of` edges; percent-complete is computed on the fly from task statuses. `ash project create/list/show/archive/progress`, `ash project task add/list/status`, `ash project milestone add/list/status`, `/workspace/*`, and a dashboard Projects tab. Also wired into `HybridSearch`. See `docs/project-workspaces.md`.

## Explicitly deferred (not in this repository yet)

These are named in the AshOS vision but require substantial additional
scope (native app integrations, media pipelines, or infrastructure this
session did not build) — the architecture above is designed so each can
land as a provider/tool/agent/plugin without kernel changes:

- **Media/creative agents**: Video (FFmpeg/Hyperframes), Vision/ComfyUI, Voice (Whisper/F5-TTS/Kokoro) — `examples/workflows/youtube-pipeline.json` shows the intended shape.
- **Browser/desktop tool integrations**: Playwright browser agent, Docker tool, VS Code integration.
- **Additional providers**: Groq, OpenRouter, local GGUF runners (same `AIProvider` pattern as Ollama).
- **Transports**: GraphQL API, WebSocket streaming, MCP server exposure.
- **Visual workflow builder** (drag-and-drop authoring of the JSON the workflow engine already executes).
- **Registry-based plugin installs** (`ash plugin install <name>` currently loads local `plugins/`; downloading from a community registry is future work).
- **Observability**: token usage / latency / GPU / CPU metrics dashboards beyond the current event-log view.
- **Security hardening**: secret encryption at rest, sandboxed tool execution, full audit-log UI.
- **Distributed execution, team/shared memory, mobile companion, cloud sync, plugin marketplace** — long-term vision items from the original spec.
- **Innovation Intelligence gaps**: five real, opt-in collectors exist (GitHub, Hacker News, Reddit, arXiv, Hugging Face) but only GitHub is live-verified in this environment — this sandbox's network policy only allowlists `api.github.com`, so the other four are real, tested code (mocked-fetch unit tests) waiting on an unrestricted environment to prove themselves live; market/workflow/competitor domains and other named sources (Papers With Code, package registries, YouTube, X) still ship only deterministic mocks; `BuilderProfileStore.reinforce()` (the Learning Loop's outcome-feedback hook) has no automatic caller yet; no automatic project/task/milestone scaffolding when an opportunity is accepted; no Weekly/Monthly reports (only the Daily Brief and the Markdown news digest); knowledge-graph entity extraction is limited to problem/technology nodes until a real collector supplies richer structure. See `docs/innovation.md`'s "What's not implemented" section.
- **AshOS Intelligence — not yet built** (full design in `docs/ashos-intelligence.md`): specialized research agents beyond Repository Analyst/Technology Radar (Research Paper Analyst, Startup Analyst, Benchmark Analyst, Documentation Analyst, API Change Analyst, Security Analyst, Trend Analyst, Opportunity Analyst); Paper Intelligence; richer Knowledge Graph relationship types and temporal reasoning; an Opportunity Engine upgrade for underserved-market/gap detection (impact/effort/confidence/strategic-value, beyond today's tag-overlap merge); a Project Matcher and Recommendation Engine tying radar/opportunity signals to the user's actual projects; Weekly/Monthly executive-briefing reports; a collector plugin marketplace for the remaining named sources.
